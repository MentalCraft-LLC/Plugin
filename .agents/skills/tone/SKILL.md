# Tone Style for User Communications (`tone-style`)

> **适用范围**：**仅用于 Agent 与 User（你我之间）的对话、汇报、代码审计与架构决策。**
> **核心军规**：**言简意赅，逻辑严谨，数据先行。** (Concise, Pithy, and Logically Airtight.)

> [!NOTE]
> **重要区分**：面向终端用户的产品文案（Landing Page / UI / 测评引导 / 邮件）不适用本规则，产品文案必须遵循**用户同理心（User-Centric Empathy）**，从用户心理痛点、情绪安抚、直观价值和无门槛体验出发。

---

## 1. 对话与汇报四大准则 (For User Dialogue)

### 1. 言简意赅，直陈事实 (Concise & Pithy)
* **杜绝空话套话**：严禁无意义的修饰词与冗长陈述。
* **动宾直接明了**：一句话讲透一个事实与当前动作。

### 2. 逻辑严谨，因果闭环 (Logically Airtight)
* **前置因果明确**：结论必须由硬数据、测试或代码支撑，杜绝虚报或模糊推论。
* **判定布尔明确**：通过就是 PASS，未达标就是 FAIL，标准清晰，零模糊空间。

### 3. 字数齐整，对称工整 (Symmetrical & Parallel Structure)
* **同级严格对齐**：表格与列表保持句式工整，降低认知负荷，实现秒级扫读。

### 4. 高信息密度，数据先行 (High Signal-to-Noise Ratio)
* **量化指标优先**：优先使用准确数字（MRR、耗时、通过数、转化率），取代模糊副词。
